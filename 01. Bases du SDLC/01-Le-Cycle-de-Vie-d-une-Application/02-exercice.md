# Exercice — Le cycle de vie d'une application (SDLC)

> **Bloc 1 · Leçon 1** — Exercice pratique, à réaliser **en autonomie**, après avoir lu `01-leçon.md`.

---

## 🎯 Objectif de l'exercice

Appliquer concrètement le SDLC à **une fonctionnalité de ton choix**, étape par étape. À la fin, tu auras produit un document complet qui prouve que tu comprends tout le cycle de vie d'une application.

---

## 📋 Énoncé

### Étape 1 — Choisis ta fonctionnalité

Choisis **une** fonctionnalité simple, réaliste et bien comprise. Quelques idées (libre à toi d'en prendre une autre) :

- Un panier d'achat sur un site e-commerce.
- Une alerte par email quand un produit revient en stock.
- Une barre de recherche de produits.
- Un formulaire de contact qui crée un ticket.
- Une fonction « réinitialiser mon mot de passe ».

> ⚠️ **Règle** : choisis une fonctionnalité que tu **comprends en tant qu'utilisateur**, même si tu n'as jamais codé. La compréhension du *parcours* est l'objectif, pas le code.

### Étape 2 — Déroule les 8 cases du cycle

Pour ta fonctionnalité, remplis **une à une** les étapes suivantes (une ou deux phrases chacune) :

1. **Besoin** : quel problème résout-on, pour qui ?
2. **Analyse du besoin** : quelles sont les attentes précises ? (qui, quoi, pourquoi)
3. **Conception** : quelle solution technique grossière envisage-t-on ? (une page web, une base, une API…)
4. **Développement** : qu'allons-nous coder concrètement ?
5. **Tests** : que doit-on vérifier pour être sûr que ça marche ?
6. **Intégration** : comment ce code s'assemble-t-il avec le reste de l'application ?
7. **Déploiement** : comment la nouvelle version arrive-t-elle en production ?
8. **Production + Monitoring + Maintenance** : comment surveille-t-on le bon fonctionnement ?

### Étape 3 — Dessine le schéma

Représente ta fonctionnalité sous forme de **schéma textuel** (comme celui de la leçon) :

```text
BESOIN
  ↓
ANALYSE
  ↓
...
```

### Étape 4 — Auto-vérification (ne regarde PAS la correction avant)

Avant d'ouvrir `03-correction.md`, réponds à voix haute (ou par écrit) à ces 3 questions :

1. À quelle étape saute-t-on si on code directement sans écouter l'utilisateur ?
2. Pourquoi les tests viennent-ils **avant** le déploiement ?
3. Que se passe-t-il si on néglige le monitoring après la mise en production ?

---

## 📦 Livrable attendu

Un document (papier, `.md`, `.txt`, fichier Notes…) contenant :

- le nom de la fonctionnalité choisie,
- les 8 cases du cycle remplies,
- le schéma textuel,
- tes 3 réponses d'auto-vérification.

> ⏱️ **Temps estimé** : 20 à 30 minutes.
